# nape-hud

Keychron Nape Pro の **レイヤー** と **OctaShift の角度** を検出し、
レイヤー切替ボタン / 8 方向切替ボタンを押した瞬間に
画面上へ数秒間ポップアップ（HUD）で表示する macOS 常駐ツール。

> 本体に回転センサーは無く、向きは **8 方向切替ボタン** の操作で切り替わる。
> 本ツールもボタン操作による状態通知を起点に表示する。

> ### 📖 使い方は [USAGE.md](USAGE.md) にまとめてある
> セットアップ・表示のカスタマイズ・コマンド一覧・トラブル対処はそちらを見ること。
> この README は **HID レポート解析の結果と経緯**（なぜこのルールになったか）を残す文書。

接続方式は **Bluetooth / 2.4GHz ドングル / USB 有線** のいずれでも動作する。
検出は macOS の IOHIDManager 経由なので、どの経路でも同じ HID デバイスとして扱われ、
接続が切り替わった場合も自動で追従する（接続種別は HUD 右下に `USB-C` / `2.4G` / `BT` と表示）。

```
┌───────────────────────────────┐
│   ╱│╲     LAYER 3            │
│  (  ↑ )   Scroll              │
│   ╲│╱     90° 縦置き  ·  BT   │
└───────────────────────────────┘
```

---

## 1. ビルド

```bash
cd ~/Desktop/nape-hud
swift build -c release
./.build/release/NapeHUD --help
```

任意で PATH に置く:

```bash
mkdir -p ~/bin && cp .build/release/NapeHUD ~/bin/nape-hud
```

## 2. サブコマンド

| コマンド | 用途 |
|---|---|
| `nape-hud` / `nape-hud run` | 常駐してレイヤー・角度の切替をポップアップ表示 |
| `nape-hud devices` | 検出したインターフェースと接続種別を一覧 |
| `nape-hud sniff` | 生 HID レポートを観測し、末尾に解析結果とルール雛形を出す |
| `nape-hud learn` | 誘導付き学習（静止 → レイヤー → 8 方向切替）でルールを自動特定 |
| `nape-hud calibrate` | 8 方向切替ボタンを 1 周させて「向きコード → 角度」の対応表を作る |
| `nape-hud keymap` | デバイスに登録されたキーアサインを読み出して表示 |
| `nape-hud test` | HUD の見た目をダミー表示で確認 |
| `nape-hud selftest` | 合成レポートで復号経路と設定書き戻しを検証（実機不要） |
| `nape-hud doctor` | 権限・設定・デバイス検出の健診 |

オプション: `-c/--config <path>` `-v/--verbose` `-p/--pointer` `-s/--seconds <n>` `-d/--debug`

`sniff` / `calibrate` は **既定 90 秒で自動終了**して結果を出す（`-s 0` で無制限、`Ctrl-C` でも即出力）。
`calibrate` は 8 方向を 1 周した時点でも自動終了する。
タイムアウトのある環境から実行しても結果を取り逃さない。

`run --debug` は一致したレポート全文と復号結果を標準出力に流す。
表示が想定と違うときの原因切り分けに使う。

```
[FF60 cmd=0xA3 状態通知（learn で確定）] A3 02 03 02 00 00 00 00 …(32B)  → layer=2 angle=135° (0x03)
```

## 3. セットアップ手順

### 3-1. 設定ファイルを置く

```bash
mkdir -p ~/.config/nape-hud
cp config.example.json ~/.config/nape-hud/config.json
```

書きたい項目だけ書けばよい（欠けた項目は既定値が使われる）。

### 3-2. レポート形式を特定する

Nape Pro は次の 3 つの HID インターフェースを持つ:

| インターフェース | 内容 |
|---|---|
| `0001/06` | 通常のキーボード / ポインタ入力 |
| `FF60/61` | QMK/ZMK 系の raw HID（Keychron Launcher が使うチャネル） |
| `008C/01` | Keychron のベンダチャネル（reportId 0xB1 / 0xB2） |

レイヤーや角度の状態が **どのバイトで来るか** は実測で決める。**`learn` を使うのが確実**。

```bash
# ⚠️ 先に Keychron Launcher のタブ／アプリを必ず閉じる（下記の注意を参照）
nape-hud learn          # 各フェーズ 25 秒（-s 20 などで変更可）
```

`learn` は観測を 3 フェーズに分け、画面の指示に従って操作するだけでルールを絞り込む。

| フェーズ | やること |
|---|---|
| 1. 静止 | **何も操作しない**。定期的に流れてくるチャタリングの素性を取る |
| 2. レイヤーのみ | レイヤー切替ボタンだけを数回押す |
| 3. 8 方向切替のみ | 8 方向切替ボタンだけを押す（1 周ぶん巡回させる） |

フェーズ 2/3 で「静止時には現れなかった値」が出たオフセットだけが候補になるため、
定期チャタリングを機械的に除外できる。最後に `config.json` にそのまま貼れる
**ルール雛形** が出力される。

> ### ⚠️ Keychron Launcher は必ず閉じる
> Keychron Launcher は WebHID で同じ `FF60` チャネルを常時ポーリングしている。
> 開いたままだとシリアル番号応答（`AB 09 …`）やセンサ応答（`A7 26 …`）が大量に混ざり、
> 状態通知と区別できなくなる。ブラウザのタブ（Arc / Chrome など）を閉じてから計測すること。

### 実測で確定している内容（Nape Pro / PID 0x0440 / 出荷時ファーム）

`config.example.json` の `rules` は下記の実測結果を反映済みなので、
同じ環境ならコピーするだけで動く。

`FF60/61` の 32 バイトレポートは **先頭バイトがコマンド ID** の多重化フォーマット。

| cmd | 内容 |
|---|---|
| **`A3`** | **状態変化通知**（`A3 <レイヤー> <向き> <DPI 段> 00 …`）。操作直後に自発的に飛ぶ |
| `AB` | シリアル番号応答（`AB 09` に続いて ASCII） |
| `A7` | Launcher の問い合わせに対する応答（センサ・バッテリ等） |
| `01` / `0C` / `11` / `12` / `14` | **VIA プロトコル**（下記） |

### VIA プロトコルに応答する

`0xFF60` は VIA の問い合わせをそのまま受け付ける（実機で確認済み）。
これを使ってキーマップを読み出しているのが `nape-hud keymap`。

| 要求 | 応答 | 実測値 |
|---|---|---|
| `01` | プロトコル版数 | 12 |
| `11` | レイヤー数 | 9（ただし実機で使えるのは 8 段。下記参照） |
| `0C` | マクロ数 | 16 |
| `12 <offset_hi> <offset_lo> <len>` | キーマップ（2 バイト/キー、ビッグエンディアン） | 9 × 7 = 63 キー |
| `14 <layer> <encoder> <cw>` | エンコーダのキーコード | ダイヤル 1 個 |

応答は先頭に要求バイト列がそのまま返るので、状態通知 `A3` と区別できる。
`0x12` は 1 往復で 28 バイトまで（32 − ヘッダ 4）。

観測されたキーコード:
`0x00D1`〜`0x00D5` マウスボタン、`0x00D9`/`0x00DA` ホイール、
`0x00A9`/`0x00AA` 音量、`0x0806`=⌘C・`0x0819`=⌘V（`QK_MODS`）、
`0x522A`/`0x522B` レイヤー関連だが意味は未確認、`0x7E29`/`0x7E2B`/`0x7E2C` Keychron 独自。

> 物理ボタンとキーコードの並び順の対応は VIA ではデバイスから取得できない
> （配列情報は VIA 定義ファイル側が持つ）。

### ポインタ加速をホスト側でやっている理由

ファーム側で加速を実装する案は現時点では成立しない。Keychron は
[`Keychron/zmk`](https://github.com/Keychron/zmk)（`rtl8762g` ブランチが活発）、
[`Keychron/hal_realtek`](https://github.com/Keychron/hal_realtek)、Zephyr フォークを
公開しているが、**Nape Pro のボード定義も PAW3222 のドライバも未公開**（全リポジトリ検索で
"nape" は 0 件、PAW も 0 件）。書き込み経路も非公開で、自前ビルドを流すと文鎮化のおそれがある。

そのためホスト側でカーソル移動イベントを書き換える方式を採った。

**デバイス判別の実測結果**: カーソル移動イベントには発生元デバイスの情報が無い。
senderID と言われる非公開フィールド 87 を実機で比較したところ、
トラックボールでも内蔵トラックパッドでも同じ値（`54240`）で判別できなかった。
そのため Nape Pro の HID 入力（usage page 1）を併せて監視し、
直前に動きがあったかで判定している（`acceleration.onlyTrackball`）。

**カーソルを実際に動かす方法**: macOS はカーソル位置を CGEvent より下層の
IOHIDEvent から決めるため、**イベントの座標や差分を書き換えても実デバイスのカーソルは動かない**。

| 方法 | 実効倍率 |
|---|---|
| セッション層タップで `location` を書き換え | 1.07x（反映率 16%） |
| HID 層タップで `delta` を書き換え | 1.00x |
| **元イベントを破棄して増幅した合成イベントを流し直す** | **3.01x** |

書き換え方式ではアプリに届く座標だけがずれて経路がジグザグになり、
macOS のシェイク検出が働いてカーソルが拡大するだけだった。
そのため最後の方式を採用している（実機の連続操作で実効 2.38x を確認）。

> 合成イベントだけで検証していたときは書き換え方式でも 2.80x が出ていた。
> 合成イベントは location と delta が自分で整合させたものなので、
> 実デバイスとの差を見逃していた。実機での検証が必要な部分だった。

### 実機の仕様（Keychron Launcher で確認）

| 項目 | 内容 |
|---|---|
| レイヤー | 全 **8** 段。状態通知は 1〜8、Launcher の表示は 0〜7 |
| OctaShift | 8 方向（0°〜315°、45° 刻み） |
| 割り当て可能 | 6 キー（**M1 / M2 / 01 / 02 / 03 / 04**）＋ ダイヤル上下 |
| 単押し / 長押し | 各キーは単押しと長押しで別の動作を割り当てられる（ユーザー設定可） |
| 保持単位 | レイヤー × 角度 × 単押し/長押し の組み合わせごと |

VIA の `0x11` は **9** を返すが、Launcher が見せるのは 8 段。
9 番目は Launcher に現れない内部レイヤーで、読み出した内容も 4〜8 段目が
すべて同一（未使用の初期値）だった。`keymap.layerCount`（既定 8）で絞っている。

Launcher の `右クリック | C(KC_UP)` のような `|` 区切りは **単押し | 長押し** を表す。

> **VIA 領域では全体を読めない**: Launcher が Layer 0 / 270° に表示する `TO(7)` と `TO(1)` は、
> VIA 領域から読めた `0x522A` / `0x522B`（差が 1）とは一致しない（TO(7) と TO(1) なら差は 6）。
> 角度別・単押し/長押し別の割り当ては別の場所に格納されている。
> その読み出しは**未実装**（ホストからの送信レポートは他プロセスから観測できないため、
> コマンドの特定には総当たりの探索が必要）。

`A3` レポートの内訳:

| offset | 内容 | 実測値 |
|---|---|---|
| 0 | cmd（固定） | `A3` |
| **1** | **レイヤー** | レイヤー切替ボタンで `01`〜`08` を巡回 |
| **2** | **向きインデックス** | 8 方向切替ボタンで `00`〜`07`（下記の順に巡回） |
| **3** | **DPI 段** | DPI 切替ボタンで `00`〜`04` の 5 段を巡回 |

`calibrate` で 1 周させた結果、向きは 8 値をこの順に巡回する:

```
0x01 → 0x02 → 0x03 → 0x04 → 0x05 → 0x06 → 0x07 → 0x00 →（0x01 に戻る）
```

同梱の `map` は `0x00` を 0° として巡回順に 45° 刻みで割り当てている。
基準にしたい向きが別なら `calibration.angleZeroCode` を書き換えるか、
アプリの校正画面で選び直す（`USAGE.md` §5）。

**offset 1（レイヤー）と offset 2（向き）は独立している。**
8 方向切替ボタンを 1 周押してもレイヤーは `1` のまま動かないことを実測で確認済み。
そのため本ツールは、角度が動いたら 8 方向切替ボタン、レイヤーが動いたらレイヤー切替ボタンと
判定して、それぞれを主役にした表示に切り替える。

> **未解決**: 過去に `A3 0B 90 02`（offset 2 = `0x90` = 144）も観測されている。
> 0〜7 に収まらないので、cmd=`A3` には状態通知以外の別種イベントが混ざっていると思われる
> （本体を持ち上げて動かしたときに出たので電源/バッテリ状態の可能性）。
> `map` に無い値は未校正として表示されるだけで誤った角度は出ないが、
> 不要なポップアップが出る場合は `nape-hud run --debug` でレポート全文を確認し、
> `match` に offset 1 の条件を足して除外する。

Launcher を閉じた状態では静止中に `A3` は 1 件も来ないので、これは
Launcher へのポーリング応答ではなく **ボタン操作による自発的な状態通知**であることが
確認できている（`learn` の静止フェーズ 25 秒で受信 0 件）。

そのため **ルールには必ず `match` で cmd バイトを指定する**こと。
指定しないと無関係な応答（`AB` のシリアル文字列など）を状態として誤読する。

> **判定順の非対称性**: レイヤーごとに向きが記憶されているため、レイヤー切替ボタンを
> 押すと offset 1 だけでなく offset 2 まで変化することがある。一方 8 方向切替ボタンは
> offset 2 のみ、DPI 切替ボタンは offset 3 のみを動かす。
> そのため判定は **レイヤー → 向き → DPI** の順で行う。
> 逆順（角度優先）にすると、レイヤー切替時にレイヤー表示が角度表示に奪われる。

### 表示のトリガ（`notify`）

ルールの `notify` で挙動を選べる。

| 値 | 挙動 |
|---|---|
| `onChange`（既定） | 値が前回と変わったときだけ表示 |
| `always` | 一致レポートが来たら毎回表示。値が同じなら直前の表示を出し直す |

各ボタンは必ず自分のバイトを変えるので、既定の `onChange` でも取りこぼさない。
`onChange` にしておくと、用途不明のバイトを動かす別ボタンで無関係なポップアップが出るのを防げる。

### 3-2b. 向きコード → 角度の対応表を作る（calibrate）

向きは `0x00`〜`0x07` の 8 値と確定しており、`config.example.json` の `map` も
実測した巡回順に沿って埋めてある。**基準の向きを変えたいときだけ** `calibrate` を使う。

```bash
nape-hud calibrate     # Launcher は閉じる
```

**基準の向き（0° とみなす向き）から始めて、8 方向切替ボタンを 1 周ぶん押す。**
ボタンは決まった順に巡回するので、押した順がそのまま向きの並び順になる。

- 新しい向きが検出されるたびに `向き #3 を検出: コード 0x03 = 3 (レイヤー 1)` のように表示される
- **最初のコードに戻った時点で自動終了**し、`angle` にそのまま貼れる `map` が出力される
- 1 周しなかった場合も既定 90 秒（`-s` で変更）で打ち切って結果を出す
- `Ctrl-C` でも即出力できる

実際の向きと合わない場合は出力された `map` の右辺の度数を手で直す。

未校正のコードは**捨てずに表示する**。HUD には角度ダイヤルの代わりに
`コード 0x2D（未校正）` と出て、起動元の端末にも一度だけ

```
⚠️  未知の向きコード 0x2D (45) を受信しました。
    `nape-hud calibrate` で angle の map に追加してください。
```

と出る。「押したのに何も出ない」状態にはならない。

`sniff` は生ログを見たいときに使う（`-v` で全レポート、`-p` でキーボード/ポインタ面も含む。
トラックボール移動で流れるので `-p` は `-s 20` などと併用する）。

### 3-3. ルールの書き方

```json
{
  "usagePage": 65376,          // 0xFF60。省略すると全インターフェース対象
  "usage": 97,                 // 0x61
  "reportId": 0,
  "minLength": 4,
  "match": [{ "offset": 0, "equals": [171] }],   // 0xAB のような固定ヘッダで種別を判別
  "layer": { "offset": 2 },
  "angle": { "offset": 3, "map": { "0": 0, "1": 45, "2": 90, "3": 135,
                                   "4": 180, "5": 225, "6": 270, "7": 315 } }
}
```

`layer` / `angle` の指定（`FieldSpec`）:

| キー | 意味 |
|---|---|
| `offset` | 読み出すバイト位置 |
| `size` | バイト数（既定 1） |
| `encoding` | `value`（数値そのまま） / `bitmaskHighest` / `bitmaskLowest` |
| `bigEndian` | 複数バイトのとき true でビッグエンディアン |
| `add` / `multiply` | 生値の補正 `(raw + add) * multiply` |
| `map` | 生値 → 表示値の明示マッピング。指定時は `add`/`multiply` より優先。**マップ外の値は無視される**（ノイズ除け） |

ZMK / QMK の `layer_state` のように **ビットマップ**で来る場合:

```json
"layer": { "offset": 2, "size": 4, "encoding": "bitmaskHighest" }
```

### 3-4. デバイスが状態を通知しない場合

ファームウェアが状態レポートを一切吐かないこともある。その場合の代替が 2 つある。

**(a) センチネルキー方式（推奨・接続方式に依存しない）**

Keychron Launcher 側で、レイヤー切替ボタンや 8 方向切替ボタンに
`F13`〜`F20` のような普段使わないキーを併発させる設定にし、それを本ツールが拾う。

```json
"keyFallback": {
  "enabled": true,
  "consume": true,
  "bindings": [
    { "keyCode": 105, "layer": 0 },
    { "keyCode": 107, "layer": 1 },
    { "keyCode": 64,  "angle": 0 },
    { "keyCode": 79,  "angle": 90 }
  ]
}
```

`consume: true` だとそのキーは他アプリに流さない（誤入力にならない）。
macOS の仮想キーコード: `F13=105, F14=107, F15=113, F16=106, F17=64, F18=79, F19=80, F20=90`。
この経路は **アクセシビリティ** 権限が必要。

**(b) ポーリング方式**

こちらから状態を問い合わせるレポートを定期送信する。
問い合わせバイト列が判明している場合のみ有効。

```json
"poll": { "enabled": true, "request": [1, 0, 0, 0], "intervalMs": 500 }
```

## 4. 必要な権限

| 権限 | 必要な場面 |
|---|---|
| 入力監視 | `0001/06`（キーボード/ポインタ面）のレポートを観測する場合 |
| アクセシビリティ | `keyFallback`（センチネルキー方式）を使う場合 |

ベンダ面（`FF60` / `008C`）の読み取りには追加権限は不要。
`nape-hud doctor` で現在の許可状況を確認できる。

## 5. ログイン時に自動起動

```bash
cp com.local.nape-hud.plist ~/Library/LaunchAgents/
# plist 内の実行パスを実際の場所に合わせて編集してから:
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.local.nape-hud.plist
```

停止 / 解除:

```bash
launchctl bootout gui/$(id -u)/com.local.nape-hud
```

ログは `/tmp/nape-hud.log`（plist で変更可）。

## 6. 表示のカスタマイズ

```json
"hud": {
  "seconds": 2.2,               // 表示秒数
  "position": "topRight",       // center | top | topLeft | topRight | bottom | bottomLeft | bottomRight
  "margin": 28,
  "scale": 1.0,                 // 全体の拡大率
  "showConnection": true,       // 接続種別バッジ
  "showOnConnectionChange": true,  // 接続/切断時にも通知を出す
  "showAngleDial": true,        // 45° 刻みの角度ダイヤル
  "followsMouseScreen": true    // マウスがある画面に出す
}
```

`layerNames` / `angleNames` で表示名を付けられる。
